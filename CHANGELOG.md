## 2026-11-08

- **feat(word): the Word task-pane add-in — search the Notees graph, insert live citations as Word fields, refresh them in place, and build a bibliography, all through the local `notees serve` bridge.** The lane ships as one record, newest slice first: **packaging** — the classic XML manifest (the shared-folder catalog does not accept unified manifests), the `/word/` dist layout the sync server serves (`NOTEES_WORD_ADDIN_DIR`), `${HOST}` resolution at build time, vendored Office.js (no CDN at runtime), and the sideload docs for Windows shared-folder, Word for the web admin-center, and Mac wef. **Badge** — the field-count badge with the host-capability fallback (read-only hosts count fields honestly instead of failing). **Style picker** — new insertions follow the picker; the explicit "Refresh all with this style" is the only thing that rewrites existing fields (a document-level switch never rewrites implicitly). **Bibliography** — insert-or-replace as one paragraph from the document's citation fields; a duplicated bibliography is reported, never silently left; the whole-paragraph replace semantics (sibling content in that paragraph is replaced) are documented and smoke-checked. **Refresh** — in-place re-render from each field's own embed, with skip-not-corrupt semantics: foreign (Zotero) and hand-corrupted fields are reported skipped and left untouched, a failed render keeps the existing text, and a bridge outage mid-run reports completed work only. **Search pane** — the debounced query → cite flow, including the stable-searchFn fix so a re-paired bridge is the one searched, and the pure engine unit-tested with injected seams. **Insert** — the citation lands as an `ADDIN notees.Citation` field at the selection (WordApi 1.5 OOXML insertion), with `CapabilityError` when the host lacks the field APIs. **OOXML + embed codec** — the pure field-code layer: the normative `{"citationId","nodeIds","styleId","locator"?}` / `{"styleId"}` embed JSON shapes, fldSimple generation, document scan, and the field-index → paragraph mapping. **Pane shell, settings, bridge client, scaffold** — the Vite+React shell with the pairing screen, the validated settings store (port + token persist across Word sessions), the typed fetch client over the bridge protocol (HTTP status surfaced so a wrong token reads rejected, not paired), and the repo scaffold with the vendored Office.js pin. Docs: `README.md` (build, `/word/` serving contract, all three sideload paths, pairing) and `docs/smoke-checklist.md` (the 15 host-only items vitest cannot cover, each checked by hand against a real Word build). Verification: full suite **132/132 green (14 files)** — `pnpm test` — with `pnpm typecheck` and `pnpm build` clean; the gate ran after every slice.
